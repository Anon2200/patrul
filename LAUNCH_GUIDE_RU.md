# Подготовка к запуску «Патруль»

Этот порядок относится к ветке `individual-auth-foundation`. Он не означает, что Production уже обновлён.

## Что должно быть настроено в ONREZA

Для сервиса `application` и окружения Production:

- `DATABASE_URL` — адрес PostgreSQL (уже был настроен ранее; перед запуском проверить, что он остался доступен).
- `PATRUL_PUBLIC_ORIGIN` — точный адрес сайта без завершающего слеша, например `https://patrul-....onreza.app`.
- `PATRUL_DATA_ENCRYPTION_KEY` — новый случайный ключ из 32 байт в формате base64url.
- `PATRUL_BOOTSTRAP_SECRET` — временный случайный секрет не короче 32 байт для создания первой учётной записи.

Не задавать `PATRUL_LEGACY_ROLE_TOKENS_ENABLED=true`. Новая версия использует персональные сессии.

## Генерация секретов

Секреты генерируются локально на доверенном компьютере в терминале с Node.js:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

Выполнить команду два раза: первый результат использовать как `PATRUL_DATA_ENCRYPTION_KEY`, второй — как `PATRUL_BOOTSTRAP_SECRET`. Не отправлять эти значения в чат, не добавлять в Git и не помещать в файлы проекта.

**Ключ `PATRUL_DATA_ENCRYPTION_KEY` обязателен для расшифровки рабочих данных.** Хранить его отдельно от базы в защищённом месте и сделать резервную копию. Потеря ключа означает потерю доступа к зашифрованным данным. Не менять ключ без отдельной процедуры ротации.

## Первичная настройка сотрудников

1. После отдельного согласованного Production-деплоя открыть сайт по HTTPS.
2. На странице входа открыть «Первичная настройка владельца системы».
3. Создать учётную запись Старшего мастера (роль `uchet`) с bootstrap-секретом и личным паролем.
4. Войти под этой учётной записью и открыть «Сотрудники».
5. Создать учётные записи Начальника (`nachalnik`), Заместителя (`zam`) и Документоведа (`dokumentoved`). Временные пароли передать каждому лично; при первом входе сотрудник должен сменить пароль.
6. После успешного создания первой учётной записи удалить `PATRUL_BOOTSTRAP_SECRET` из переменных Production и перезапустить сервис.

## Проверки перед рабочим использованием

- Войти по очереди под каждой из четырёх учётных записей.
- Проверить, что сотрудник видит только свой раздел и не может открыть чужую роль.
- Создать тестовую запись, сохранить её, обновить страницу и проверить, что запись осталась.
- Проверить передачу зашифрованного пакета между Документоведом и Старшим мастером в обе стороны.
- Проверить работу с двух устройств и убедиться, что конфликт версий не перезаписывает более свежие данные.
- Настроить и проверить резервную копию PostgreSQL, а также отдельно сохранить ключ шифрования.

## Важные ограничения

- Для работы и синхронизации нужен интернет.
- Вручную скачанные JSON-резервные копии и CSV-экспорты содержат открытые данные; хранить их только в защищённом месте.
- План платформы может усыплять сервис при простое; первое обращение после простоя может быть медленнее.
- Не объединять эту ветку с Production и не запускать деплой, пока владелец системы отдельно не согласовал переключение и пока не выполнены проверки выше.
