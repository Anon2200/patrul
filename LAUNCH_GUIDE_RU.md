# Подготовка к запуску «Патруль»

Эта инструкция относится к итоговой сборке в ветке `launch-hardening` (PR #5 в `feature/shared-data-center`). Автоматические проверки GitHub Actions проходят; Production пока остаётся на старой версии.

## 1. Переменные ONREZA

Для сервиса `application`, окружения Production:

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | Адрес PostgreSQL. По предыдущей настройке уже задан; перед запуском убедиться, что он не изменён |
| `PATRUL_PUBLIC_ORIGIN` | `https://patrul-ippolitovartem63-ms5l.onreza.app` |
| `PATRUL_DATA_ENCRYPTION_KEY` | Случайный ключ ровно 32 байта, закодированный в base64url (или 64 hex-символа) |
| `PATRUL_BOOTSTRAP_SECRET` | Временный случайный секрет минимум 32 байта |

Сгенерировать два разных значения локально в терминале Node.js:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

Запустить команду два раза. Первый результат — для `PATRUL_DATA_ENCRYPTION_KEY`, второй — для `PATRUL_BOOTSTRAP_SECRET`. Не отправлять значения в чат, не добавлять их в Git и не помещать в файлы проекта.

**Ключ шифрования критически важен.** Сервер использует его для шифрования данных ролей в PostgreSQL и при старте проверяет возможность расшифровки существующих строк. Хранить ключ отдельно от базы и иметь резервную копию. Потеря ключа означает потерю доступа к зашифрованным данным. Не менять ключ без процедуры ротации.

Не задавать `PATRUL_LEGACY_ROLE_TOKENS_ENABLED=true`: новая версия использует персональные сессии. Старый `PATRUL_API_TOKEN` не нужен новой авторизации; его можно пока оставить без использования.

## 2. Первая учётная запись

После согласованного Production-деплоя:

1. Открыть сайт по HTTPS.
2. На экране входа раскрыть «Первичная настройка владельца системы».
3. Создать учётную запись Старшего мастера (роль `uchet`), используя `PATRUL_BOOTSTRAP_SECRET`, личный логин и пароль длиной не менее 12 символов.
4. Войти под этой учётной записью и открыть «Сотрудники».
5. Создать учётные записи Начальника (`nachalnik`), Заместителя (`zam`) и Документоведа (`dokumentoved`). Временный пароль показывается только при создании; передать его сотруднику лично. При первом входе сотрудник обязан установить свой пароль.
6. После успешного создания первой учётной записи удалить `PATRUL_BOOTSTRAP_SECRET` из Production-переменных и перезапустить сервис.

## 3. Как работает синхронизация

- Изменения отправляются автоматически примерно через 700 мс после последнего действия, если соединение доступно.
- При временной сетевой ошибке приложение повторяет отправку с увеличивающейся задержкой.
- При конфликте версий сервер не перезаписывает более свежие данные. Пользователь получает предупреждение; локальные изменения сохраняются в резервную копию, если браузер может её скачать.
- Для работы необходим интернет. Перед закрытием вкладки дождаться статуса «подключено · сохранено».

## 4. Проверка перед рабочим использованием

Проверить вручную в браузере:

- Войти под каждой из четырёх учётных записей.
- Убедиться, что каждая учётная запись открывает только назначенную ей роль.
- Создать тестовую запись, дождаться статуса сохранения, обновить страницу и проверить сохранность.
- Проверить обмен зашифрованным пакетом между Документоведом и Старшим мастером в обе стороны.
- Проверить одновременную работу с двух устройств и сценарий конфликта версий.
- Настроить резервное копирование PostgreSQL и проверить восстановление на отдельной тестовой базе.
- Сохранить ключ шифрования отдельно от резервной копии базы.

## 5. Ограничения и эксплуатация

- Автоматические тесты не заменяют ручную проверку браузера и реальных устройств.
- Вручную скачанные JSON-резервные копии и CSV-экспорты содержат открытые данные; хранить их в защищённом месте.
- На текущем тарифе платформа может усыплять сервис при простое; первое обращение после простоя может быть медленнее.
- Ограничитель попыток входа хранит счётчики в памяти одного процесса; поведение за reverse proxy и при нескольких репликах требует отдельной проверки.
- Перед включением реальных рабочих данных завершить ручную проверку и проверку восстановления резервной копии.
