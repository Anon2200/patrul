# Подключение PostgreSQL для «Патрульной службы»

## Что реализовано

- Node.js HTTP-сервер (server.js).
- Проверка соединения: GET /api/health.
- Хранилище JSON по четырём ролям: nachalnik, zam, uchet, dokumentoved.
- Отдельный серверный секрет для каждой роли.
- Токен одной роли не даёт читать или изменять данные другой роли.
- Сравнение секретов выполняется с защитой от timing-атак.
- После 10 неверных попыток для одной роли с одного IP сервер временно блокирует новые попытки на оставшуюся часть 5-минутного окна (HTTP 429 и Retry-After); успешная авторизация сбрасывает счётчик.
- Контроль версии при записи: устаревшее сохранение получает HTTP 409 и не затирает более свежие данные.
- Таблица patrul_role_data создаётся сервером при старте.
- Клиент хранит ключ роли только в sessionStorage текущей вкладки.

## Переменные окружения сервиса ONREZA

1. DATABASE_URL — подключение PostgreSQL через интеграцию. Не публикуйте и не присылайте его.
2. PATRUL_TOKEN_NACHALNIK — случайный секрет для раздела «Начальник».
3. PATRUL_TOKEN_ZAM — отдельный случайный секрет для раздела «Заместитель».
4. PATRUL_TOKEN_UCHET — отдельный случайный секрет для раздела «Старший мастер».
5. PATRUL_TOKEN_DOKUMENTOVED — отдельный случайный секрет для раздела «Документовед».

Каждый секрет должен быть длинным, случайным и отличаться от остальных (рекомендуется не менее 32 случайных байт). Секреты задаются только в серверных переменных ONREZA; не добавляйте их в Git, HTML, JavaScript или сообщения. Старый PATRUL_API_TOKEN больше не используется этой версией.

Команда запуска: npm start. Требуется Node.js 20 или новее.

## Проверки

- `npm run check` — синтаксис JavaScript и структура страниц.
- `npm run test:integration` — интеграционные проверки с тестовой PostgreSQL.
- Интеграционный тестовый процесс сам задаёт отдельные временные тестовые токены; секреты Production не нужны в GitHub Actions.
- GitHub Actions запускает оба набора проверок автоматически.

## Важные ограничения перед запуском

Разделение секретов — промежуточная мера, не полноценные индивидуальные учётные записи. Пользователи внутри одной роли пока используют общий ключ этой роли. Нет персональных аккаунтов, администрирования пользователей, журналирования действий и завершения сессий на сервере.

Данные в PostgreSQL хранятся как JSONB и не имеют прикладного шифрования. Не вводите реальные служебные или персональные данные, пока не будут реализованы индивидуальная авторизация, серверные права доступа, аудит, резервное копирование с проверкой восстановления и оценка требований законодательства о персональных данных.

Production не следует переключать на эту ветку до изолированного тестирования, настройки новых переменных и отдельного плана безопасного перехода. Не удаляйте старые секреты или данные в рамках подготовки тестовой версии.
