# PostgreSQL и серверная конфигурация «Патруля»

Актуальная кодовая база: ветка `main`. Сервер запускается командой `npm start` (Node.js 20 или новее). Документ описывает текущую схему, включая независимое хранение графика и ежедневного наряда.

## Что хранится в PostgreSQL

- `patrul_role_data` — отдельные рабочие данные четырёх основных кабинетов (`nachalnik`, `zam`, `uchet`, `dokumentoved`).
- `patrul_shared_staff` — единый зашифрованный список личного состава, отделений, сопоставлений идентификаторов и комплектов постов.
- `patrul_duty_schedule` — назначения отделений на посты и подмены старших по датам. История графика сохраняется.
- `patrul_duty_rosters` — ежедневный состав наряда, времена, отметки снаряжения, недочёты, происшествия и итоги.
- `patrul_patrol_senior_credentials`, `patrul_patrol_senior_invites`, `patrul_patrol_senior_entries` — привязки Старших патруля, одноразовые приглашения, PIN-хэши и записи службы.
- `patrul_tasks`, `patrul_task_events`, `patrul_task_notifications` — общие поручения, история статусов и уведомления.
- `patrul_mail_threads`, `patrul_mail_participants`, `patrul_mail_messages`, `patrul_mail_attachments` — внутренняя почта и вложения.
- `patrul_users`, `patrul_sessions`, `patrul_audit_log` — персональные учётные записи, сессии и журнал аудита.
- `patrul_document_counters` — последовательная нумерация документов по году.

## Миграции

При запуске `server.js` автоматически применяет миграции `001_identity_schema.sql`–`010_independent_duty_storage.sql` в порядке номеров. Перед первым запуском новой схемы в рабочей базе обязательно:

1. Сделать резервную копию PostgreSQL.
2. Проверить, что ключ шифрования сохранён отдельно и доступен.
3. Убедиться, что `DATABASE_URL` указывает именно на требуемую базу.
4. Сверить резервную копию и процедуру восстановления на отдельной тестовой базе.

**Важное изменение миграции 010:** при первом запуске новой версии сервер переносит из старого поля `duty` только назначения и подмены календаря. Старые ежедневные составы нарядов, отметки, времена, снаряжение, недочёты, происшествия и отчёты из старого поля намеренно не переносятся; старое поле `duty` удаляется из данных начальника. Не запускайте обновление на рабочей базе, пока не согласованы это поведение и резервная копия.

## Переменные окружения ONREZA

Для сервиса приложения в Production:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Строка подключения PostgreSQL |
| `PATRUL_PUBLIC_ORIGIN` | Точный HTTPS origin сайта: `https://patrul-ippolitovartem63-ms5l.onreza.app` |
| `PATRUL_DATA_ENCRYPTION_KEY` | Ключ шифрования: 32 случайных байта в base64url или 64 hex-символа |
| `PATRUL_BOOTSTRAP_SECRET` | Временный секрет первичного создания системного администратора, минимум 32 байта |
| `PATRUL_TIME_ZONE` | Необязательно; часовой пояс ежедневной очистки, по умолчанию `Europe/Berlin` |

Сгенерировать каждый секрет отдельно в доверенном локальном терминале:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

Не отправляйте секреты в чат, не добавляйте их в Git и не помещайте в документацию. **Не теряйте и не меняйте `PATRUL_DATA_ENCRYPTION_KEY` без отдельной процедуры ротации:** без прежнего ключа зашифрованные данные нельзя расшифровать. Храните ключ отдельно от резервной копии БД.

После успешного создания первой учётной записи удалите `PATRUL_BOOTSTRAP_SECRET` из Production-переменных и перезапустите приложение. Не включайте `PATRUL_LEGACY_ROLE_TOKENS_ENABLED=true`: штатный вход использует персональные сессии.

## Ежедневная очистка

Сервер запускает очистку при старте и затем каждый день в 00:00 в часовом поясе `PATRUL_TIME_ZONE` (по умолчанию `Europe/Berlin`). Удаляются ежедневные наряды и записи журнала Старшего патруля за даты раньше текущей местной даты. Назначения графика в `patrul_duty_schedule` не удаляются и остаются историей.

## Проверки

- `npm run check` — синтаксис JavaScript и статические проверки страниц.
- `npm run test:integration` — интеграционные проверки с отдельной тестовой PostgreSQL.
- GitHub Actions выполняет проверки при pull request в `main` и при push в `main`.

## Эксплуатационные замечания

Первый вход и подключение нового устройства требуют интернета. Старший патруля может продолжить работу с журналом в ранее авторизованной вкладке в пределах восьмичасового офлайн-окна; локальный кэш и очередь шифруются, а повторная отправка защищена от дублей. Контрольный просмотр других кабинетов Старшим мастером работает только для чтения и фиксируется в аудите.

Ограничитель попыток входа хранит счётчики в памяти процесса. При нескольких репликах или за reverse proxy требуется отдельная проверка. Перед полноценной эксплуатацией необходимо вручную проверить резервное копирование и восстановление PostgreSQL.
