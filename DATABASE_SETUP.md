# PostgreSQL и серверная конфигурация «Патруля»

Документ относится к рабочей сборке в ветке `feature/complete-role-platform-20261115` (черновой PR #39). PR не объединён; Production не переключён.

## Что хранится в PostgreSQL

- `patrul_role_data` — рабочие данные четырёх основных кабинетов; перед записью они шифруются AES-256-GCM.
- `patrul_shared_staff` — единый зашифрованный список личного состава и отделений.
- `patrul_patrol_senior_credentials`, `patrul_patrol_senior_invites`, `patrul_patrol_senior_entries` — привязка старших патрулей к отделениям, одноразовые коды активации, PIN-хэши и журнал смен.
- `patrul_tasks`, `patrul_task_events`, `patrul_task_notifications` — общие поручения, история статусов и уведомления.
- `patrul_mail_threads`, `patrul_mail_participants`, `patrul_mail_messages`, `patrul_mail_attachments` — внутренняя почта и вложения.
- `patrul_users` — персональные учётные записи и хэши паролей.
- `patrul_sessions` — хэши сессионных токенов, сроки действия и отзыв.
- `patrul_audit_log` — события входа и административные действия.

Схема идентификации применяется сервером при старте. Старые открытые строки рабочих данных шифруются при старте до начала обслуживания запросов.

## Переменные окружения ONREZA

Для сервиса `application`, окружения Production:

1. `DATABASE_URL` — адрес PostgreSQL. Не публиковать и не присылать в чат.
2. `PATRUL_PUBLIC_ORIGIN` — точный HTTPS origin: `https://patrul-ippolitovartem63-ms5l.onreza.app`.
3. `PATRUL_DATA_ENCRYPTION_KEY` — ровно 32 случайных байта, закодированных в base64url, либо 64 hex-символа.
4. `PATRUL_BOOTSTRAP_SECRET` — временный случайный секрет не менее 32 байт для создания первой учётной записи.

Сгенерировать секреты локально через Node.js:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

Запустить команду отдельно для каждого секрета. Не отправлять секреты в чат и не добавлять в Git. Ключ шифрования хранить отдельно от БД и обязательно резервировать. После создания первой учётной записи удалить `PATRUL_BOOTSTRAP_SECRET` и перезапустить сервис.

Старый `PATRUL_API_TOKEN` не используется новой персональной авторизацией. Не включать `PATRUL_LEGACY_ROLE_TOKENS_ENABLED=true`.

## Проверки

- `npm run check` — синтаксис JavaScript и статические проверки страниц.
- `npm run test:integration` — интеграционные проверки с отдельной тестовой PostgreSQL.

## Эксплуатация

Первый вход и подключение нового устройства требуют интернета. Старший патруля может продолжить журнал смены без сети в ранее авторизованной вкладке до 8 часов; локальный кэш и очередь шифруются AES-GCM в IndexedDB. При восстановлении связи серверная сессия проверяется повторно, а отправка очереди защищена от дублей миграцией 009. Другие роли и разделы продолжают требовать интернет. Контрольный просмотр других кабинетов доступен Старшему мастеру только для чтения и фиксируется в аудите. Платформа может усыплять сервис при простое. Перед Production следует сделать резервную копию PostgreSQL и проверить восстановление на отдельной тестовой базе. Ключ шифрования должен быть сохранён независимо от базы: без него восстановленная БД не сможет расшифровать рабочие данные.
